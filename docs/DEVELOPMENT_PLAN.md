## 1. 项目立项宗旨与反模式规避

### 1.1 为什么上一代项目会“练废”？
在前序项目（`Multi-Board-Game-Collection`）的长期开发中，累积了以下不可逆的技术与设计债务：
1. **2D 与 3D 的割裂（油水分离）**：3D 场景沦为纯粹的画布背景，所有关键操作（暂停、重开、悔棋、步数、设置、AI 状态、结算）依然堆砌在 2D HTML/CSS 浮层上。玩家始终感知到“我是在操作一个套了 3D 皮肤的网页后台”。
2. **状态蔓延与 DOM 耦合**：逻辑状态在 DOM 类名、控制器属性、渲染器内部变量之间来回倒手，导致加一个新功能就需要同时改动 DOM、CSS、State、Renderer 等多个松散模块，极易引发回归。
3. **视觉弹窗对沉浸感的扼杀**：胜利弹窗、提示 Toast、设置抽屉频繁阻断视觉流动，打断对弈者的心流体验。

### 1.2 Zenith-Tabletop-3D 的核心设计守则
- **【守则一：零 2D 浮层原则】**：对弈视口内**坚决不出现任何传统 HTML 按钮、弹窗遮罩或文字 Toast**。一切交互均由桌案上的真实 3D 实体承载。唯一例外是屏幕底部的宣纸提示卡（`ui/Hud.js`）：只在**终局之后**（左右两侧指向两只棋罐，说明如何再来一局）、**新手指导进行中**与**刚复原一盘棋时**（说明轮到哪一方）出现，落子对弈期间从 DOM 中移除。
- **【守则二：以视点推移代替界面跳转】**：需要查看详情或调校规则时，由空间平滑镜头推至目标实体特写；离开时点击桌面空白处平滑退回对弈主视角。
- **【守则三：纯净单向数据流】**：`src/core/` 业务逻辑层 100% 独立于 Three.js 和 DOM，支持在 Node.js 中进行毫秒级独立测试。状态驱动实体动画，禁止在动画回调中私自纂改游戏规则状态。

### 2.1 实体一：双面机械对局钟 (Dual Mechanical Chess Clock)
- **物理外观**：
  - 精工红木箱体，倾斜 15° 双石英指针表盘，顶部双金属按压跷跷板，侧边黄铜机械发条与制动旋钮。
- **功能职责**：**暂停游戏 (Pause) / 恢复对局 (Resume) / 双方用时监控**。
- **交互与物理反馈**：
  - **动态指针渲染 (Dynamic Canvas Texture)**：表盘数字与秒针由离屏 `OffscreenCanvas` 动态绘制，并作为材质贴图实时驱动秒针每秒平滑走动。
  - **暂停操作**：鼠标或触控点击侧边黄铜制动扳手，扳手物理弹起并伴随清脆的金属制动机械声（“咔哒”）；钟摆秒针骤停；相机缓动推近进入钟表特写，场景光影变为静止晨雾。再次点击扳手压下，恢复对局并推回主镜头。
  - **行棋敲钟**：当玩家或 AI 在棋盘落子后，顶部对应一侧的金属跷跷板在 80ms 内弹起，另一侧按落，平滑切换思考方。

### 2.2 实体二：回溯黄铜沙漏 (Rewinding Sandglass)
- **物理外观**：
  - 黄铜双立柱雕花支架，双锥形高透水晶玻璃球体，内部盛装细密金沙。
- **功能职责**：**悔棋 (Undo)**。
- **交互与物理反馈**：
  - 玩家点击沙漏时，沙漏沿中心转轴执行 **180° 翻转物理动效**（耗时 400ms，带缓动惯性）；
  - 玻璃内部沙粒逆向倒流（流体粒子动效）；
  - 棋盘上最后落下的棋子周围泛起微风光尘，垂直升空 3 厘米，划出一条优美的抛物线平滑飞回对应的棋罐中；
  - 数据层执行 `undoMove()`，状态回溯。

### 2.3 实体三：线装古籍与悬空墨笔 (Strategy Manual & Floating Brush)
- **物理外观**：
  - 平铺在棋盘左上方的古朴线装书，泛黄宣纸质感，旁置青瓷水盂与一支竹管狼毫笔。
- **功能职责**：**战术提示 (Hint) / AI 大模型棋道导师 (QI Coach)**。
- **交互与物理反馈**：
  - 点击古籍时，镜头顺滑旋转俯冲至古籍上方（研读视点）；
  - 书页无风自动掀开一页，悬空毛笔蘸墨，在宣纸表面以行草书法的墨迹动画实时绘制出：
    1. **推荐落子点**（如“宜着于 G8”）；
    2. **战术意图批注**（如“断其二路活三，兼固右翼”）；
    3. **局势气势折线**（淡墨山水风格的气势图）。
  - 同时，棋盘上对应的推荐坐标交点处缓缓升起一缕半透明青烟微光。
  - 点击古籍外任意区域，镜头拉回。

### 2.4 实体四：桌案皮质记谱册 (The Leather Score Ledger)
- **物理外观**：
  - 右下角的深棕色真皮装订横线笔记本，配有一支复古黄铜墨水钢笔。
- **功能职责**：**记谱记录 (Move History) / 手数统计 / 历史步数复盘**。
- **交互与物理反馈**：
  - 每当双方落子，钢笔自动在记谱册最新一行流畅书写（`1. H8 2. I9 3. G7...`），伴随沙沙的书写音效；
  - 玩家点击笔记本，镜头推近右侧；玩家可点击书角翻页回溯历史；
  - 鼠标悬停在某一历史步数上，主棋盘会自动以 40% 半透明幽灵光晕投影出当时那一手的棋局残影。

### 2.5 实体五：黑白天然原木棋笥 (Crafted Go Bowls)
- **物理外观**：
  - 黑方为天然黑胡桃木棋罐，白方为天然白蜡木棋罐，打磨圆润，表面具微弱蜡光反射。罐盖虚掩在一侧。
- **功能职责**：**开局阵营选边 (Color Selection) / 吃子与存子统计**。
- **交互与物理反馈**：
  - 开局阶段，无任何单选框弹窗。玩家直接点击揭开黑胡桃木罐，即代表执黑先行；点击白蜡木罐即代表执白后手；
  - 选定后，罐盖自动移至棋盘边作为定置台。

### 2.6 实体六：朱砂兽钮青田石印章 (The Vermilion Victory Stamp)
- **物理外观**：
  - 摆放在桌案角落的一方高浮雕兽钮青田冻石印章，配有青花印泥盒。
- **功能职责**：**终局胜负裁定与仪式感结算 (Game Over Ceremony)**。
- **交互与物理反馈**：
  - 当形成五子连珠（或违例禁手、认输）时，系统彻底抛弃全屏弹窗；
  - 镜头猛然拉起为宏大的 80° 俯瞰全景，桌案边的一方巨石印章凌空浮起、在印泥盒中轻触，随后沉重砸向对局卷轴中央！
  - 伴随着沉闷雄浑的物理撞击共鸣音，卷轴上重重盖下一方朱红篆刻大印——“大捷”、“完胜”或“承让”；
  - 印记周围激荡出金色纸屑微粒，五子连线棋子高亮闪烁，仪式感拉满。

## 3. 空间镜头导演系统详细规范 (Spatial Camera Director Spec)

### 3.1 视点状态机 (Camera Viewport State Machine)

| 视点状态 (State) | 相机位置 (Position: x, y, z) | 注视焦点 (Target: x, y, z) | 视野角度 (FOV) | 用途说明 |
| :--- | :--- | :--- | :--- | :--- |
| **MAIN_PLAY** (默认对弈) | `[0.0, 13.0, 16.2]` | `[0.0, 5.0, -4.0]` | 56° | 玩家落座后的第一人称视角（镜头位于近侧人物的头部）：略俯视全盘，画面顶部能看到对面棋手的头与肩，底部一行交点仍可点击 |
| **CLOCK_FOCUS** (时钟特写) | `[10.2, 7.8, 6.5]` | `[8.5, 2.0, 1.0]` | 35° | 推近机械对局钟，调校时间、查看秒针、按下暂停 |
| **MANUAL_STUDY** (古籍研读) | `[-7.8, 10.5, 3.2]` | `[-6.5, 0.5, -2.0]` | 32° | 俯拍宣纸古籍，细品 AI 水墨提示与局势点评 |
| **LEDGER_REVIEW** (记谱翻看) | `[7.5, 9.2, 8.5]` | `[6.0, 0.5, 4.5]` | 34° | 推近皮质笔记本，翻页回溯历史每步落子 |
| **VICTORY_DRAMA** (终局巡礼) | `[0.0, 22.0, 4.5]` 动态环绕 | `[winX, 0.0, winZ]` | 38° | 终局聚焦获胜连线，环绕巡礼特写 |

### 3.2 运镜阻尼曲线与物理插值
- 采用 **Hermite Slerp（球面双三次插值）** 计算相机位置矢量与目标注视点矢量；
- 缓动函数采用 Cubic Ease-In-Out：
  $$t' = t < 0.5 ? 4t^3 : 1 - \frac{(-2t + 2)^3}{2}$$
- 过渡周期统一严格控制在 **600ms ~ 800ms**，既有行云流水的仪式感，又绝不浪费玩家操作时间。
- **逃逸机制**：处于特写视点时，点击屏幕任意非道具区域（桌面或棋盘），立即以 500ms 高速平滑切回 `MAIN_PLAY` 视角。

## 4. 核心业务与规则架构 (Domain Core Engine)

业务层代码位于 `src/core/`，**严禁引入任何 Three.js 或 DOM API**，保证 100% 纯净度与可测性。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            src/core/ 纯净业务架构                           │
│                                                                             │
│  ┌───────────────────────┐   ┌───────────────────────┐   ┌────────────────┐ │
│  │   state/GameState.js  │   │    rules/Gomoku.js    │   │  ai/Search.js  │ │
│  │  - 不可变快照 (Freeze) │   │  - 连五判定           │   │  - 启发式评分  │ │
│  │  - 历史动作栈 (History)│   │  - 连珠禁手 (三三/四四)│   │  - Alpha-Beta  │ │
│  │  - 思考计时器状态     │   │  - 有效性与提子校验   │   │  - 杀棋剪枝    │ │
│  └───────────────────────┘   └───────────────────────┘   └────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.1 不可变状态快照体系 (Immutable Snapshots)
- 任何一次落子（`makeMove`）、悔棋（`undoMove`）、暂停（`togglePause`）均返回全新的不可变状态对象：
  ```javascript
  const nextState = GameEngine.transition(currentState, {
    type: 'MAKE_MOVE',
    row: 7,
    col: 7,
    timestamp: performance.now()
  });
  ```
- 状态机向外广播标准事件：`onMoveCommitted`, `onTurnSwitched`, `onStateReverted`, `onGameFinished`。

### 4.2 规则与禁手引擎 (Renju Forbidden Moves)
- 经典规则与连珠禁手双模式并行；
- 禁手引擎以落子点为核心，沿 4 个轴向（$0^\circ, 45^\circ, 90^\circ, 135^\circ$）扫描棋型模式（`FOUR_PATTERNS`、`THREE_PATTERNS`）；
- 准确识别“活三”、“假活三（因禁手阻断成四）”、“冲四”、“长连（6子以上）”；
- 毫秒级断言，单测用例涵盖全部极端死活题。

## 5. 三维空间声学系统 (3D Positional Audio Architecture)

摒弃传统平庸的单声道播放，新系统全面接入 Web Audio API 空间声场（`PannerNode`）：

1. **真实三维物理声源定位**：
   - 棋盘落子声音源位于落子点坐标 $(x, 0, z)$，黑子白子根据坐标真实分布在左右耳立体声场中；
   - 机械对局钟每秒的清脆滴答声与按落声，精确来源于右前方 $(+8.5, 0, +1.0)$；
   - 翻书声来自左前方 $(-6.5, 0, -2.0)$。
2. **材质级物理采样音效库**：
   - **木石相击 (Stone on Wood)**：榧木板特有的厚重清脆触击音（瞬态 12ms，混响尾音 180ms）；
   - **机械制动 (Clock Plunger)**：精密机械咬合声与弹簧回弹震颤；
   - **沙粒回流 (Sand Trickle)**：高频细密沙流轻音；
   - **宣纸翻折 (Parchment Flip)**：纤维摩擦与纸张风声。

## 8. 质量保障与验收标准 (QA & Acceptance Criteria)

1. **零 2D 污染验收**：
   - 检查整局游戏（从开局选边、对弈落子、查看计时、暂停、悔棋、看提示、到终局结算），DOM 树中除了 `<canvas id="webgl">` 之外，不得渲染任何业务按钮与模态弹窗；底部提示卡仅允许在终局盖印之后、导览期间与复原棋局后的选边阶段存在，且必须在新一局落子前消失（`npm run smoke` 会在对弈中校验 `<body>` 下只有 canvas）。
2. **运镜平滑度**：
   - 视点切换（对弈视角 ↔ 特写视角）在 60 FPS 满帧运行，无明显掉帧与视觉突跳，Slerp 插值无奇点抖动。
3. **逻辑纯净度**：
   - `src/core/` 目录运行 `npm test`，所有规则、禁手判定、AI 评分单测 100% 在无浏览器无 DOM 环境下极速通过。
